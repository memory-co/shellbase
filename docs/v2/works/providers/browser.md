# 网页浏览器 provider

```python
BrowserSpec(id, url)  →  Instance(window_url=<VNC URL>, handle=<CDP>)
```

## 一个实例 = 一个 webmuxd session

**不是一个 tab。** 这一条改过一次，理由值得写下来，免得以后有人再提「共享一个
session、每块占一个 tab」这个方案：

> webmuxd 的窗是 **VNC**——它传的是那个 session 的**画面**。多个 tab 在同一个浏览器
> 实例里，VNC 只能显示当前活动的那一个。两个块嵌着同一个 VNC URL，看到的就是
> 完全一样的画面，谁切 tab 另一个块也跟着变。**共享 session 在视觉上根本不成立。**

要让每个块显示各自的 tab，得让画面按 tab 分流（CDP screencast 而非 VNC），
那是另一套实现面。在窗是 VNC 的前提下，**一块一个 session 是唯一正确的粒度**。

代价照实认：一个 session 是一整个桌面镜像（4 GB 级），起得慢、占得多。
所以下面两条策略都是围着这个成本转的。

## 端口从哪来

[M5](../muxd-spec.md) 说端口必须由调用方传、不自动分配。多实例就需要多个端口，
于是**端口段由部署传入**：

```python
BrowserProvider(webmuxd=Webmuxd(), ports=range(7900, 7910), idle_timeout=1800)
```

池子用完就报「没有空闲端口了，段是 7900-7909」，**不去自己找一个空闲端口**——
猜出来的端口会让防火墙、反代、部署文档全部对不上。这跟 M5 的理由是同一个。

## 窗与把手

| | 是什么 | 备注 |
| --- | --- | --- |
| 窗 | VNC URL | **实现面**，可以换（KasmVNC / TigerVNC / Selkies），换了上层无感 |
| 把手 | CDP | **契约面**，换掉它等于换掉这个组件（[muxd-spec §5](../muxd-spec.md)） |

逃生舱：自己拿 DevTools 连上去，看到的和它看到的是同一份 target 表。

## 生命周期

- **起**：`get()` 时占一个端口、要一个 session，然后 `open(url)`；
- **收**：贵，所以**保留期分钟级**（默认 30 分钟闲置）。终端可以放到天级，
  浏览器不行——一个闲置的 session 压着 4 GB；
- **关块不立刻收**，仍然遵守「活得比连接久」：你关掉块去干别的，十分钟后回来，
  登录态和滚动位置还在。**分钟级保留期就是在这条承诺和成本之间划的线。**

## 站内跳转要跟着走

CDP 能报出当前 URL，所以**块的 URI 应当跟随页面实际跳转更新**——刷新回到「你现在
在的那一页」，而不是最初那个地址。这是 v1 明确做不到的一条（跨域读不到 iframe 的
location），换成真浏览器之后就成立了。

## 失败长什么样

| 情况 | 怎么说 |
| --- | --- |
| webmuxd 不可用 | `Unavailable`，带装它的那条命令。**不退回 iframe**（M13） |
| 端口池满 | 报「段是 7900-7909，都占着」，并列出占着它们的实例 |
| 页面卡死 | 实例还活着，画面不动。`alive()` 说的是 session，不是页面——**别把这两件事混为一谈** |

## 做不到的

- **不是「点开就有」**。镜像大、首帧慢，秒开的只读预览这条路给不了；
- **画面经 VNC 传**，文字锐度和延迟不如本地渲染；
- **下载、剪贴板都在那台远端浏览器上**。下下来的文件落在服务器，要拿回来走
  [文件浏览器](files.md)；
- **不做多 tab 管理界面**。一个块一个 session 一个页面；要看两个页面就开两个块。
