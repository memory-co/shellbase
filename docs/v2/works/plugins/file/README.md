# `file://` · 浏览一个目录

```
file:///workspace            浏览这个目录
file:///workspace/a.py       落在这个文件上
```

## path

本机路径，**必须存在**。目录就展开它，文件就定位到它并打开内容。

路径锚定在 workspace 根下，越界一律拒绝（[v1 files API](../../../../v1/api/files.md)）——
这条不因为换了协议层就松动。

## 形态

**只有文件浏览器**，背后就是 shellbase 自己的文件 API，没有 `*muxd` 组件。

这说明 provider 与组件是多对多的：**一个 provider 背后不一定有组件**
（[protocol.md §5](../../protocol.md)）。

**要不要给它一个终端形态**（ranger / yazi 这类 TUI 文件管理器）：技术上成立，
且不违反「不改语义」——那仍然是「浏览这个目录」。**但现在不做**，理由是收益不值：
它要求机器上装一个额外的二进制，而换来的能力与现成的文件浏览器高度重叠。
**写在这里是为了说明这是个取舍，不是遗漏。**

## 会话

**没有会话。** `session_id()` 返回 `None`——文件浏览器背后没有长驻进程，
每次打开都是对文件系统的一次读。

这是三种会话形态里的第三种（另两种是「每块一个」和「同 path 共享」）。
画布层看到 `None` 就不去向组件要 session，也不为这个块做「活得比连接久」的假设。

## 做不到的

- **不是一个编辑器。** 它能改文件（mtime 乐观锁），但没有 vim 的键位、没有多光标、
  没有插件——要那些用 [`vim://`](../vim/)；
- **大目录会慢**。树是按需展开的，但单层几万个条目仍然会卡。这是已知的，
  没有分页设计。
