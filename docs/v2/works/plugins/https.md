# `https://` · 打开一个页面

```
https://example.com/x           外部站点
https://localhost:5173/         本机上跑着的服务
```

`http://` 同属这个 plugin。

## path

**网址本身**，不是文件系统路径——这是「path 的语义归 plugin 解释」
（[protocol.md §1](../protocol.md)）最直白的一个例子。

## 形态

**只有网页浏览器。** 但这一种形态背后有两条承载路径，选哪条由 plugin 决定，
**不由用户切 provider**——对用户来说都是「一个页面」：

| 情况 | 承载 |
| --- | --- |
| 默认 | 前端 iframe 直接装载 |
| host 是 `localhost` / `127.0.0.1` | 经网关的 `/proxy/<port>/` 反代（[v1 uri §3](../../../v1/works/uri.md)） |
| 页面拒绝被嵌入，或需要程序驱动 | webmuxd 的窗 |

**为什么 localhost 必须走代理**：浏览器里的 `localhost` 指的是用户自己的设备，
不是跑着 shellbase 的那台机器。不代理的话，用户看到的是自己电脑上的 80 端口。

**为什么 webmuxd 不是默认**：那是一整个桌面镜像（4 GB 级）。为了看一眼页面就把它拉起来，
代价和收益不成比例。**它该在被需要时才出现**——页面设了 `X-Frame-Options` 嵌不进来，
或者要让程序去点、去填。这属于 plugin 的实现选择，不是 `?as=` 能切的东西：
形态始终是「网页浏览器」，换的只是背后的组件。

## 会话

沿用默认，每块一个。同一个页面开两个块是合理的（比如对照两个环境）。

iframe 那条路径其实没有会话可言；只有落到 webmuxd 时才真的有一个 session。
**这个差异对用户不可见，但影响「关掉块之后还在不在」**——iframe 关掉即消失，
webmuxd 的 session 活得比连接久。

## 做不到的

两条限制是**前缀式代理的固有代价**，v1 已经踩过：

- **根路径资源会逃出 `/proxy/<port>/`**。页面里 `<link href="/style.css">` 会被浏览器
  拼成 shellbase 自己的地址，而 SPA 兜底会返回 200 + HTML，于是「页面出来了但样式全没」。
  规避：页面用相对路径，或加 `<base href="/proxy/<port>/">`，或给 dev server 配 `base`；
- **站内跳转追不到**。跨域读不到内层 iframe 的 location，所以块的 URI 停在最初那个地址，
  刷新会回到它而不是用户当前所在的页。同源（`/proxy/` 那条）理论上追得到，现在也没做。

根治要么在网关里重写 HTML/CSS 与 `Location`（脏，且对 JS 动态拼的 URL 无解），
要么改成按端口分子域名（要泛域名和证书）。**两条都不在现在的范围里，先诚实写着。**
