# `https://` · 打开一个页面

```
https://example.com/x           外部站点
https://localhost:5173/         本机上跑着的服务
```

`http://` 同属这个 plugin。

## path

**网址本身**，不是文件系统路径——这是「path 的语义归 plugin 解释」
（[protocol.md §1](../protocol.md)）最直白的一个例子。

## 形态：网页浏览器，背后是 webmuxd

**只有这一条路**。页面在服务器那侧的一个真浏览器里打开，shellbase 拿到的是 webmuxd
报出的窗，把它摆进块里。**没有 iframe 兜底**——见下面「依赖」。

这是一整个桌面镜像的代价（4 GB 级、起得慢），换来的是四件 iframe 给不了的事：

- **人和程序看同一块**。能点能填，也能让程序去点去填（CDP 把手）。iframe 只能看，
  跨域连当前地址都读不到；
- **没有嵌入限制**。`X-Frame-Options` / `frame-ancestors` 与我们无关了——
  我们不嵌入任何东西，我们是在开浏览器；
- **`localhost` 直接就是对的**。浏览器跑在服务器上，`https://localhost:5173` 里的
  localhost 就是那台机器。**v1 那层 `/proxy/<port>/` 前缀代理在这条路上不再需要**，
  它踩过的两个坑（根路径资源逃出前缀、SPA 兜底把 CSS 请求答成 200 的 HTML）
  从根上消失；
- **站内跳转追得到**。CDP 能报出当前 URL，块的 URI 可以跟着走——刷新回到「你现在
  在的那一页」，而不是最初那个地址。这是 v1 明确做不到的一条。

> `/proxy/<port>/` 本身在 v2 不会消失，但用途只剩一个：**把组件报出来的窗透出去**
> （[protocol.md §5](../protocol.md)）。「看本机服务」不再走它。

## 会话

每块一个。session 活得比连接久——关掉网页，那个 tab 还在那儿开着
（[M6](../muxd-spec.md)）。

## 依赖

webmuxd 可用。不可用时按 [M13](../muxd-spec.md) **报不可用，并给出装它的那条命令**，
**不偷偷退回 iframe**——退回去用户会以为看到的是同一个东西，直到他想让程序点一下
才发现不是。这正是 M13 说的「装作有比没有更糟」。

## 做不到的

- **不是「点开就有」**。一个块一个浏览器实例，镜像大、首帧慢。想要秒开的只读预览，
  这条路给不了；
- **画面经 VNC 传**，文字锐度和延迟不如本地渲染。看文档尚可，做像素级的事不行；
- **剪贴板、下载、上传都在那台远端浏览器上**。下载下来的文件落在服务器的下载目录里，
  不在你自己的电脑上——要拿回来得走文件浏览器。
