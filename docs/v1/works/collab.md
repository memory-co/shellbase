# shellbase v1 多人协作设计

> 借鉴 tmux 的多客户端模型，把 [backend.md](backend.md) 中的 state 做成**可共享**的：
> 多个人（或一个人多台设备）打开同一个页面，看到并操作的是同一份现场。

## 1. 模型：state 是共享单元，打开只是 attach

tmux 的协作哲学是：会话（现场）独立于客户端存在，客户端只是"看向"它的窗口——可以有任意多个，来了就镜像、走了不影响。shellbase 把这个模型推广到两层 state：

| 层 | state | 共享含义 |
|----|-------|----------|
| 终端 | `terminals/<id>.json` + tmux 会话 | 同一终端被多个浏览器块同时 attach，输出实时镜像、皆可输入 |
| 页面 | `windows/<id>.json` | 同一张页面被多个浏览器同时打开，分割/换应用实时互见 |

任何"打开"动作都不独占资源，也不复制资源——attach 到已有 state 就是加入协作。

## 2. 终端共享：tmux 天然给的

同一条完整终端 URI 被 N 个浏览器块 attach 时，每个 ttyd 连接各自执行 `attach.sh` → `tmux new-session -A` 挂到**同一个 tmux 会话**：输出对所有客户端实时镜像，任何一方都能输入。这就是 tmux 原生的结对模式，后端零额外工作。（会话身份 = 完整 URI，自含 `window`/`block`，见 uri.md §4——协作的入口就是进入同一个 window、打开同一条 URI；不同客户端打开同一 window 时布局同步，块的 URI 相同，自然 attach 到同一现场。）

两个需要显式定的策略：

- **尺寸**：多客户端窗口大小不一时，默认 `set -g window-size latest`（跟随最后操作的客户端），避免所有人被最小窗口截断；
- **只读观看**：attach 端点支持 `?mode=ro`，302 时把参数带给 ttyd，`attach.sh` 据此改用 `tmux attach-session -r`——观看者看得到、打不进。只读 attach 不触发无中生有（观看一个不存在的会话没有意义，直接 404）。

典型场景：一个人在终端块里跑 Claude Code，其他人打开同一个块围观 Agent 干活；需要接手时任何人直接敲键盘即可。

## 3. 页面共享：同一个 window，所有浏览器同步

window 状态存在服务端（backend.md §4），"多个人打开同一个页面"就是多个浏览器进入同一个 `/#w/<id>`，`GET /api/windows/{id}` 拿到同一棵树；不同 window 之间互不干扰（A 在 `main` 干活，B 在 `review` 看代码，各自独立协作域）。这也是 shellbase **唯一的分享形式——分享以 window 为粒度**：把 `/#w/<id>` 链接发出去即可，不支持分享单个块（uri.md §5）——要给同伴看一个终端，就把它所在的 window 给对方。要让同 window 协作是**实时**的，补一条广播通道：

- `WS /api/windows/{id}/watch`：后端在该 window 每次成功写入后，向其所有连接广播新 `version`；
- 客户端收到大于本地的版本号即拉取新树、重渲染布局——diff 应用：块的 id/应用未变则 iframe **原地保留不重建**，终端不闪断，只有真正新增/关闭/移动的块发生变化；
- 并发编辑靠单调 `version` 兜底（backend.md §4.2）：谁后写谁生效；被 409 拒绝的一方拉最新树、在其上重放本地改动。

于是协作图景是：A 把页面一分为二并开了个 Claude Code，B 的页面随即长出同样的块；两人盯着同一个终端现场，谁都可以接管输入——tmux pair programming 的网页版。

**关闭是销毁性操作**：布局共享意味着关闭块对所有人生效——终端块的关闭还会真正杀掉 tmux 会话（backend.md §4.2"关闭即销毁"），同伴正盯着的现场会一起消失。因此前端在 `clients > 1`（会话正被多个客户端 attach）时必须二次确认后再关。

## 4. 边界与后续

- v1 的"多人"指**多个持同一 token 的客户端**——单用户多端，或共享凭据的小团队。区分身份、按人授权（谁只读、谁可写）依赖多用户体系，属 design.md §1.3 排除项；届时 state 结构不变，只在 attach 时多一层身份判断；
- 在线感知（presence：谁在看这个页面/这个终端）可基于 attach 记录与 WS 连接列表实现，作为 v1.1+ 增强，不影响现有协议；
- 浏览器块、文件块的"共享"以块参数为粒度（URL、路径随布局同步），块内的浏览历史、编辑器未保存内容仍是各客户端本地的——v1 不做块内内容级的实时协同（如共享编辑器光标），这是刻意的简化。
