# shellbase v1 启动页设计（Launcher）

> 每个空白块的默认内容是一张**启动页**——类似浏览器的新标签页：浏览器让你选择进入哪个网站，
> shellbase 让你选择进入哪个应用；每个应用记录最近使用，点一下即可复用（重入）。

## 1. 定位

启动页出现在三种场合，是同一个页面（`/apps/launcher`，本身也是一个 iframe 应用）：

1. **新分割出的空白块**：默认装载启动页，选完应用后原地替换为目标 URI 的解析结果；
2. **首次进入 shellbase**（后端无布局）：整页就是一个启动块；
3. **块被关闭回收后重新利用**：回到启动页。

启动页的本质是 [uri.md](uri.md) 所说的 **URI 构造器**加上**最近记录簿**：一切选择的终点都是产出一条 URI，交给 Shell 装载。

## 2. 界面

```
┌──────────────────────────────────────────────────┐
│  [URI 直达栏]  bash:// file:// https:// … 直接粘贴 │
├──────────────────────────────────────────────────┤
│   应用宫格                                        │
│   ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐   │
│   │ 终端  │ │ 文件  │ │ 浏览器│ │Claude│ │Codex │   │
│   └──────┘ └──────┘ └──────┘ └──────┘ └──────┘   │
│   （宫格内容 = 应用注册表：内置 + SHELLBASE_APPS_EXTRA）│
├──────────────────────────────────────────────────┤
│   最近使用（按应用分组 / 按时间混排，可切换）          │
│   ▸ codex:///workspace/myproj        2 小时前  ●  │
│   ▸ bash:///workspace/build          昨天      ●  │
│   ▸ https://localhost:5173/          昨天         │
│   ▸ file:///workspace/notes.md       3 天前       │
│     （● = 现场仍存活，点击即重入；无点 = 重新加载）    │
└──────────────────────────────────────────────────┘
```

交互流两条路，殊途同归于一条 URI：

- **走应用**：点宫格 → 该应用的参数表单（Agent/终端选工作目录、浏览器给地址栏、文件给路径选择器），表单内嵌该应用自己的最近记录；终端类按 uri.md §4.1 处理同路径已存活的情况（接入 / `tab` 新开）；
- **走记录**：直接点最近使用条目，原 URI 原样装载——终端类就是重入原现场。

## 3. 最近使用记录（recents）

### 3.1 存储：前端本地，不跨设备

recents 是**使用习惯**而非工作现场，存在前端 localStorage，各浏览器私有、不进后端 state、不跨设备同步：

```js
// localStorage["shellbase.recents"]
[
  { "uri": "codex:///workspace/myproj", "last_opened": "2026-07-28T09:00:00Z", "count": 17 },
  { "uri": "https://localhost:5173/",   "last_opened": "2026-07-27T18:20:00Z", "count": 5 }
]
```

- 按规范化 URI 去重（同一现场只留一条，`last_opened`/`count` 累积；`tab≥2` 的实例是独立身份、独立条目）；
- 上限 200 条，LRU 淘汰；条目提供单条删除与一键清空。

### 3.2 采集与存活标注

- **采集**：Shell 每次成功装载一个块就记一笔，无论入口是启动页还是 deep link；唯独**布局恢复不记**——恢复不算"使用"，否则每次刷新都会把全部条目的时间戳冲掉；
- **存活标注**：启动页渲染时调用 `GET /api/terminals`（backend.md §2.4），把返回的存活会话与本地终端类条目对照，标出"仍存活"圆点——用户一眼分清"重入现场"和"从头再来"。后端不为 recents 增加任何端点。

## 4. 与其他文档的关系

- 启动页产出 URI、消费本地 recents——是 [uri.md](uri.md) 的交互皮肤；
- 后端零改动：不新增存储与端点，仅复用已有的 `GET /api/terminals` 做存活标注（[backend.md](backend.md)）；
- 多人协作（[collab.md](collab.md)）下 recents **各自私有**：它记录的是个人使用习惯；要把入口交给同伴，用块上的"复制定位符"分享 URI 本身。
