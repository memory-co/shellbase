# shellbase v1 Rich URL bar 设计

> shellbase 没有独立的"启动页"。每个块的入口是一条 **rich URL bar**——像浏览器的 omnibox：
> 聚焦即展示最近使用与应用宫格，开始输入即变为自动补全。空白块里的输入框、
> 面板栏上的地址栏，是同一个组件、同一套行为。

## 1. 定位

- **取代启动页**：不再有一张独立的选择页面（早期设计中的 `/apps/launcher`），"选应用 / 点记录"全部收敛进 URL bar 的下拉层——入口不是一个页面，而是一条无处不在的 bar；
- 出现的场合：
  1. **空白块**（新分割出的块、关闭回收后的块、首次进入时的整页）：块内容区只渲染一条居中的 URL bar，自动聚焦；
  2. **已有内容的块**：面板栏上的地址栏就是同一条 rich URL bar（design.md §3.6）——聚焦后同样给出下拉层，改 URI 即换应用/跳转；
- 本质仍是 [uri.md](uri.md) 所说的 **URI 构造器**加上**最近记录簿**：一切交互的终点都是产出一条构造形态 URI，交给 Shell 落位（补全 `window`/`block` 身份参数，uri.md §4）。

## 2. 交互：一个输入框，两种下拉状态

```
聚焦、未输入                                 开始输入
┌────────────────────────────────┐    ┌────────────────────────────────┐
│ ▏                              │    │ code▏                          │
├────────────────────────────────┤    ├────────────────────────────────┤
│  应用宫格                       │    │  ▸ codex:///workspace/myproj   │
│  ┌────┐ ┌────┐ ┌─────┐ ┌────┐  │    │  ▸ codex:///workspace/demo     │
│  │终端│ │文件│ │浏览器│ │Codex│ │    │  ▸ claude:///workspace/code-x  │
│  └────┘ └────┘ └─────┘ └────┘  │    └────────────────────────────────┘
├────────────────────────────────┤     （宫格消失，recents 就地变为
│  最近使用                       │       autocomplete 候选列表）
│  ▸ codex:///workspace/myproj   │
│  ▸ bash:///workspace/build     │
│  ▸ https://localhost:5173/     │
└────────────────────────────────┘
```

两种状态间由"是否有输入"自动切换：

- **聚焦、未输入**：下拉层分两区——**应用宫格**在上，**最近使用**（按时间排序）在下。宫格**不靠注册机制**：内容 = recents 按 scheme 聚合后**最近使用的 10 个 scheme**，每个 scheme 一格（`vim://` 用过就上宫格，无需任何登记）；没有最近使用时才退化到应用注册表条目（内置终端/文件/浏览器 + `SHELLBASE_APPS_EXTRA`，见 api/system.md `GET /api/apps`）——注册表退居冷启动兜底与元数据（标题/图标/别名）；
- **开始输入**：宫格消失，recents 就地变为 **autocomplete**——按子串匹配 URI（scheme、路径分段都参与匹配），`↑`/`↓` 选择、`Enter` 确认；输入内容本身是合法 URI 时 `Enter` 直接打开——未注册的 CLI（`vim://`、`htop://`…）由此进入（uri.md §3.1）；
- **点宫格**：把该应用的 URI 模板预填进输入框（终端/Agent 预填 `<scheme>:///workspace`、浏览器预填 `https://localhost:`、文件预填 `file:///workspace`），光标留在参数位继续编辑——参数表单就是输入框本身，recents 随前缀自动过滤为该应用的记录；`settings://` 这类无参应用点击即直接打开；
- **点击/确认 = 永远新开**：产出的都是构造形态 URI，Shell 落位补全 `window` + 新分配的 `block` → 全新现场（uri.md §4.1）。下拉层**不做存活标注**，也没有"接入现有会话"入口——归属不变量 + 关闭即销毁保证存活现场必然已有块在展示它，本 window 里"重入"一个存活现场只会造出两个镜像块；重入语义由布局恢复独自承担（分享也是 window 级别、走同一条布局同步，uri.md §5），不经过 URL bar 的候选列表；
- `Esc` / 失焦收起下拉层。空白块的 bar 收起后仍在（它就是块的全部内容）；面板栏地址栏收起后回到只读展示当前 URI。

### 2.1 自定义输入：终端块改 URI = 销毁重建

地址栏支持完全自由的手敲输入，不限于候选与宫格。但对**已有内容的终端块**提交新 URI 时，语义不是"跳转"而是**销毁重建**：终端现场没有原地导航可言（tmux 会话的 cwd 与命令一经创建不可变更），旧现场按"关闭即销毁"注销（`DELETE /api/terminals`，backend.md §4.2），新 URI 再按构造形态落位为全新现场。因此提交前必须**弹确认提醒**——用户要知道旧终端里的东西会没掉；`clients > 1`（现场正被同伴 attach）时提醒同 collab.md §3 的关闭确认。浏览器/文件块改 URI 只是换加载目标，无销毁语义，不需确认。

### 2.2 身份参数不可手填

用户输入中的 `window`/`block`（包括整条粘贴进来的完整 URI）在落位时**一律被剥离重写**：`window` = 当前 window，`block` = 新分配的最小空闲号——无论填什么都会被 overwrite。这条规则保障一致性：

- 手敲 URI 永远不可能破坏归属不变量（uri.md §4），也不可能靠猜号接管/镜像既有现场；
- URL bar 因此只有一种输出——构造形态 + Shell 补全，没有"带着外来身份参数落位"的旁路；
- 分享是 **window 级别**的：可分享的 URL 只有 window 链接 `/#w/<id>`（uri.md §5），不支持分享单个块——因此**不存在任何接受外来完整 URI 的入口**，完整形态只在布局 state 内部流转。

## 3. 最近使用记录（recents）

### 3.1 存储：前端本地，不跨设备

recents 是**使用习惯**而非工作现场，存在前端 localStorage，各浏览器私有、不进后端 state、不跨设备同步：

```js
// localStorage["shellbase.recents"]
[
  { "uri": "codex:///workspace/myproj", "last_opened": "2026-07-28T09:00:00Z", "count": 17 },
  { "uri": "https://localhost:5173/",   "last_opened": "2026-07-27T18:20:00Z", "count": 5 }
]
```

- 条目存**构造形态**：终端类 URI 剥离 `window`/`block` 身份参数后规范化去重——recents 记的是"常用哪个应用 + 哪个目录"这个习惯，不是具体现场；同路径多实例合并为一条，`last_opened`/`count` 累积；
- 上限 200 条，LRU 淘汰；条目提供单条删除与一键清空。

### 3.2 采集

- Shell 每次成功落位一个块就记一笔（剥身份参数后入账），空白块与面板栏地址栏两个入口同等对待；唯独**布局恢复不记**——恢复不算"使用"，否则每次刷新都会把全部条目的时间戳冲掉；
- 点击 recents 条目 = 按构造形态重新落位（新 `block`、新现场，§2）。不做存活标注：会话身份已由 `window`/`block` 隔离，存活现场必然正被某个块展示（uri.md §4.1），条目无需也无法代表"某个具体现场"。

## 4. 与其他文档的关系

- URL bar 产出 URI、消费本地 recents——是 [uri.md](uri.md) 的交互皮肤：构造形态由它产出，完整形态的补全在 Shell 落位时发生；
- 后端零依赖：下拉层纯本地渲染（recents + 注册表兜底数据 `GET /api/apps`），不调用会话查询端点，也不为 recents 新增任何存储与端点（[backend.md](backend.md)）；
- 多人协作（[collab.md](collab.md)）下 recents **各自私有**：它记录的是个人使用习惯；要把现场交给同伴，分享 window 链接（`/#w/<id>`）——布局同步会把块原样带给对方（uri.md §5）。
